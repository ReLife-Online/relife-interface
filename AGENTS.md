# ReLife development rules
- JavaScript generates the HTML, CSS, and R audit program. index.html is only a module entry point.
- Use class-centered systems with constructor lifecycle setup and nested associative registries for systems, functions, and events.
- Prefer JavaScript. Use R for explicit numeric audits; do not add Python or Docker. Use systemd if a local service is needed.
- Any while loop must consist only of function calls / round trips. Prefer bounded for loops for binary processing.
- Keep uploaded binaries on the user's device. Never execute uploaded or disassembled code. Repository modules are a separate, explicitly trusted source path.
- The public frontline is ChatGPT Sites at relifeonline.site. GitHub Pages uses the same public loader; do not assign the apex domain to GitHub Pages.
- Source modules come only from ReLife-Online/ReLife-Online.github.io, ReLife-Online/relife-core, and ReLife-Online/relife-interface. Add new sources through a reviewed allowlist change.
- Preserve open bytes, patches, offset, selected tab, and pending patch inputs across module updates. Never reload automatically.
- Tests must cover byte-exact round trips, truncated instructions, patch boundaries, and mirror route restrictions. Do not claim full decompilation or source compilation.
